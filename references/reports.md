# 报告体例与维护

报告是 skill 的交付物。前面几章查的是"扫没扫到"，这份文档管的是"交出去的东西长什么样"。

版式照商用扫描器的主机报表抄：A4、上下页边距 2.54cm、左右 3.17cm、微软雅黑、表格浅蓝细边
（`#9ACAE1`）、表头行填充 `#DCEBF0`、键列填充 `#EAF5F9`、正文墨蓝 `#122347`。这些值在
`reporter.CSS` 与 `docx_writer.THEME` 里各存一份，**改一处要改两处**，不然两份报告的颜色对不上。

产出在 `data/runtime/reports/<run_id>/`，五份文件同源，数字不会互相打架：

| 文件 | 角色 | 说明 |
| --- | --- | --- |
| `report.html` | 主件 | 自包含单文件，样式内联，不引外部字体、图标和脚本；离线双击可开，也可直接打印 |
| `report.docx` | 可编辑件 | 标准库拼的 OOXML（`zipfile` + 手写 XML，不引 python-docx）；打开时自动重算目录页码 |
| `report.pdf` | 打印件 | 由 HTML 转出（weasyprint），没装就跳过，不影响其余四份 |
| `report.md` | 文本版 | 同一份数据的纯文本，给工单系统和邮件正文用 |
| `report.json` | 结构版 | 归档与二次处理用；`findings` / `severity_counts` / `risk_score` / `blocked` 都在里面 |

## 章节结构

封面 → 目录 → 正文六章 → 附录四则 → 声明。章节号用阿拉伯数字（`1` / `1.1`），与商用报告一致。

| 章节 | 写什么 |
| --- | --- |
| 1 综述信息 | 1.1 任务信息（键值表）、1.2 风险分布（1.2.1 主机风险分布、1.2.2 风险等级分布）、1.3 评估依据。开门第一句先给结论：涉及几个对象、几条风险、风险值多少、判为哪一档 |
| 2 风险类别 | 2.1 按风险类型统计、2.2 按来源工具统计；两张表同构：分类 ｜ 严重 ｜ 高危 ｜ 中危 ｜ 低危 ｜ 提示 ｜ 合计 |
| 3 风险清单 | 序号、风险名称、等级、（多目标时的）评估对象、来源工具、交叉验证、证据摘要 |
| 4 风险详情 | 每条一节：评估对象（多目标时）、风险等级、来源工具、交叉验证、判定依据、证据、加固建议 |
| 5 脆弱凭据 | 口令 / 凭据类发现单列，不复述明文；没有就写清"未获取到可确认的凭据" |
| 6 参考标准 | 6.1 单一风险等级评定标准、6.2 主机风险等级评定标准、6.3 网络风险等级评定标准（区间 + 权重）、6.4 安全建议。先立规则再出结论 |
| 附录 A | 工具执行记录；被安全策略拦下的步骤单列一张表 |
| 附录 B | 审计链校验结果与复核方式 |
| 附录 C | 工具原始输出，折叠展示，仅作核对用 |
| 附录 D | 交叉验证推翻的条目（原条目、原定级、原证据、推翻理由）。没有推翻条目时这一附录不出现 |
| 声明 | 保密声明与责任声明，措辞与封面一致 |

## 等级与风险值口径

工具给的是英文档位，报告里一律换成中文，并按"可造成的直接影响"定级，不以工具自身告警级别为准：

| 档位 | 报告写法 | 权重 | 建议处置时限 |
| --- | --- | --- | --- |
| critical | 严重 | 3 | 立即处置（24 小时内） |
| high | 高危 | 2 | 3 个工作日内 |
| medium | 中危 | 1 | 2 周内 |
| low | 低危 | 0.5 | 随版本迭代 |
| info | 提示 | 0 | 无需处置，留存记录 |

风险值 = Σ(各等级条目数 × 权重)，上限 10 分。这个口径能把商用报告里"7 条低危 = 3.5 分"对上，
报告里的每个数都能倒推。分两级用同一套权重、不同区间：

| 档位 | 主机风险值（该主机上的条目求和） | 网络风险值（整个评估范围求和） |
| --- | --- | --- |
| 非常危险 | 7.0 ≤ 值 ≤ 10.0 | 8.0 ≤ 值 ≤ 10.0 |
| 比较危险 | 5.0 ≤ 值 < 7.0 | 5.0 ≤ 值 < 8.0 |
| 比较安全 | 2.0 ≤ 值 < 5.0 | 1.0 ≤ 值 < 5.0 |
| 非常安全 | 0.0 ≤ 值 < 2.0 | 0.0 ≤ 值 < 1.0 |

区间写在 `HOST_BANDS` / `RISK_BANDS`，报告 6.2 / 6.3 两张表由 `_band_rows()` 从同一份数据生成，
不会出现"分数对不上档位"。模型偶尔会给出 `moderate`、`severe` 这类别名，`_sev_key()` 负责归一，
别让没见过的档位在报告里变成空标签。

## 体例上的几条硬约定

这些不是审美偏好，是"这份东西要打印、盖章、交给甲方"倒推出来的：

- **不写没有依据的处置承诺。** 第 4、6 章的加固建议按工具类别给通用动作（关端口、收敛暴露面、
  升级组件、加认证），到这一层为止。业务改造方案由使用方定，报告里不替它拍板。
- **被拦下的步骤必须进报告。** 高风险动作被授权闸门挡住时，附录 A 要能看出哪些动作没做、
  为什么没做。只写"做了什么"的报告，会让看的人以为范围已经覆盖全了。
- **被推翻的条目也不能静默删掉。** 交叉验证判为推翻的条目附理由进附录 D，1.1 节与结论里写明本轮
  推翻了几条。看报告的人要能判断这份清单是筛过的还是漏的 —— 只报留下的部分，等于替甲方做了决定。
- **交叉验证这一列只在真跑过时出现。** `verdict` 字段由 `verifier` 写入，直接调用 `reporter` 的场景
  没有这一列，报告里不会凭空多出一个空栏目。
- **工具没跑完时，不套用该工具的加固建议。** 那一条本来就取自工具的结论，工具没出结论就无从谈起，
  正确写法是提示补测。
- **单目标不重复同一列。** 整轮只扫一台机器时，清单和详情里不再加"评估对象"列；多目标（网段、
  多 IP、多站点）才带，否则每行都在重复同一个地址。
- **排版不用渐变、圆角胶囊和图标。** 屏幕上好看的那套放到纸面上就散了；表题在表上方、
  图题在图下方、页码在页脚居中，这些是在向排版出来的文档靠。
- **封面只有第 1 页不编页码**，其余页脚写"第 X 页 共 Y 页"（`@page :first` + `counter(pages)`；
  Word 侧用 `PAGE` / `NUMPAGES` 域）。

## 改哪里

- 章节内容：`scripts/agents/reporter.py` 里的 `_summary_chapter` / `_category_chapter` /
  `_list_chapter` / `_detail_chapter` / `_credential_chapter` / `_standard_chapter` / `_appendix_*`。
  HTML 与 Word 是同一份数据的两个渲染器：HTML 侧返回 HTML 片段，Word 侧在 `_docx_blocks()` 里
  用同一套数据拼 blocks，**改章节的时候两边都要动**。
- 正文文案：`TXT_*` 常量（保密 / 责任 / 目的 / 方法 / 无发现等）。两份报告都从这里取字，
  免得出现"同一轮任务两个格式的说法不一样"。
- 加固建议的词条：`_ADVICE_GROUPS`，按工具名分组，命中不到时落到 `DEFAULT_ADVICE`。
- 等级口径：`SEV_LABEL` / `SEV_CRITERIA` / `SEV_DUE` / `SEV_STYLE` / `RISK_WEIGHT` / `HOST_BANDS` /
  `RISK_BANDS` 一起改，别只改一个。
- HTML 样式：`CSS` 常量。给表格指定列宽时走 `_table(..., widths=(...))`，
  不加 `table-layout:fixed` 的话 weasyprint 会按内容重新分配，窄列照样被撑宽。
- Word 版式：`docx_writer.py` 的 `THEME` 与 `SZ_*` 字号。目录用真 TOC 域，`settings.xml` 里开了
  `updateFields`，Word 打开时自动重算页码；没更新域时域里缓存的那份纯文字目录也能看。

改完在 skill 目录跑一次 `python3 evals/smoke.py`，再随便跑一轮任务（网段目标要跑一遍，
验证多目标那几个分支），用浏览器打开 `report.html`、用 `pdftoppm` 逐页看 PDF 的分页，
用 Word 或 `python3 -c "import docx; docx.Document('report.docx')"` 确认 docx 打得开。

**报告体例的改动算交付物变更** —— 动了就要在 `skill-card.md` 的修订记录里记一笔并升版本号，
`SKILL.md` / `BENCHMARK.md` / `evals/evals.json` 里的版本字段一并跟上。
