# 漏洞扫描知识库 — 扫描方法论与 CVE 映射

> 用途：漏洞扫描 Agent 的核心操作手册。CVE 映射流程、误报排除、CVSS 评分速查、默认凭证表。

---

## 一、CVE 匹配 → 验证 → 利用 标准流程

```
service_identify 取得服务指纹(名称+版本)
    ↓
cve_match_sm_por(服务版本) 查询 CVE 数据库
    ↓
筛选：CVSS ≥ 7.0 优先，是否 RCE/高危
    ↓
vuln_verify(target, cve) 确认真实性【关键步，排除误报】
    ↓
已确认 → 尝试 poc_runner_sm_por / 手工验证
标记误报 → 报告中注明，不进入利用
    ↓
输出漏洞明细
```

**核心规则**：任何 CVE 未经 `vuln_verify` 确认不得作为"已确认漏洞"报告，最多标记"疑似"。

## 二、误报排除 5 场景

1. **版本误报** — 扫描到的版本号模板匹配过宽，实际未受影响
   - 解决：核对该 CVE 的受影响版本区间是否包含实际版本
2. **服务误判** — service_identify 把 nginx 误判为 Apache
   - 解决：多端口交叉验证，结合响应头
3. **补丁已装** — 系统已打补丁，但 banner 仍显示旧版本
   - 解决：vuln_verify 做实际请求验证（发送探测 payload）
4. **配置豁免** — 漏洞存在但特定配置已缓解（如 WAF 拦截、参数过滤）
   - 解决：vuln_verify 绕过 WAF 语义验证
5. **误报模板** — CVE 模板与目标实际技术栈不匹配（CMS 插件匹配错）
   - 解决：核对指纹归属

**判定规则**：
- vuln_verify 返回"已确认" → 进入报告
- vuln_verify 返回"误报" → 报告中注明，不进入利用
- vuln_verify 返回"待验证" → 标记 ⚠️ 需进一步验证

## 三、CVSS v3.1 评分速查

| 评级 | CVSS 分数 | 处理优先级 |
|------|----------|-----------|
| 🔴 严重 Critical | 9.0 - 10.0 | P0 紧急（24h 内） |
| 🟠 高危 High | 7.0 - 8.9 | P1 尽快（72h 内） |
| 🟡 中危 Medium | 4.0 - 6.9 | P2 计划（30 天内） |
| 🟢 低危 Low | 0.1 - 3.9 | P3 建议（90 天内） |

### 关键评分要素（粗算口径）
- **攻击向量**：网络(0.85) > 相邻(0.62) > 本地(0.55) > 物理(0.20)
- **利用复杂度**：低(0.77) > 高(0.44)
- **权限要求**：无(0.85) > 低(0.62) > 高(0.27)
- **影响**：完全(0.56) / 高(0.56) / 低(0.22)

### 常见分值规律（帮助快速判断）
- 未授权远程 RCE：CVSS ≈ 9.0 - 10.0（严重）
- 需认证的 RCE：CVSS ≈ 7.0 - 8.9（高危）
- SQL 注入（未授权）：CVSS ≈ 8.0 - 9.8
- 反射型 XSS：CVSS ≈ 5.0 - 6.1（中危）
- 存储型 XSS：CVSS ≈ 6.1 - 6.5（中危）
- 信息泄露/版本泄露：CVSS ≈ 4.0 - 5.3（中低危）

## 五、扫描优先级决策矩阵 (P0-P3)

| 场景 | 优先级 | 理由 |
|------|--------|------|
| 未授权远程 RCE | P0 | 直接可被攻陷 |
| 未授权 SQL 注入 | P0 | 直接可拖库 |
| 弱口令 + 公网暴露 | P0 | 可直接登录 |
| 高版本已知 RCE(需利用) | P1 | 较高风险 |
| 存储型 XSS | P1 | 可窃取会话 |
| 敏感信息泄露 | P2 | 中危 |
| 缺安全响应头 | P3 | 低危，加固项 |
| 版本号泄露 | P3 | 信息类 |

## 六、报告结构要求

- 四档分级全量输出（严重/高危/中危/低危），无则写占位符
- 每个漏洞附带实际证据（工具输出关键行）
- 修复建议具体可执行（不只是"升级版本"，给出版本和加固命令）
